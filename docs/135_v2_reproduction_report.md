## 1. 一句话结论

- 论文的**方法**已经端到端可运行，并且两种实现都能接入真实 Spectre：
  - v1：只有两个决策点由 LLM 决定；
  - v2：Manager / Searcher / Refiner 都是 LLM ReAct 智能体，与论文一致。
- 在**同一工艺、同一口径**下，v2 与 v1 的通过率接近：
  - N65 S1–S8：v2 21/40，v1 24/40；
  - N65 S9/S10：两者都是 S9 4/5、S10 0/5。
- v2 的明显优势有两处：
  - 在代理后端的 S9s/S10s 上，v2 6/10，v1 0/10；
  - 在 N65 S9/S10 上，v2 用的 Spectre 约为 v1 的 1/3。
- 论文中**没有复现**的部分：
  - S6/S7/S10 这类最难的规格；
  - "LLM 是 S9/S10 成功关键"这一结论：在 N65 上 v1 规则同样能做 S9。

## 4. 没有复现的原因（已有证据）

- **S3（N65）**：50 GHz 下 RF 管 fT ≈ 110–120 GHz，单管 NFmin 已有 2.1–3.7 dB（docs/132 §4）。器件受限。
- **S6/S7**：宽带 S11 与 NF 的冲突，以及输入匹配的损耗。S7 用 PDK 螺旋电感（Q 35–49）也没有改善；Ls 小于最小的螺旋，无法用螺旋实现（docs/133 §8）。
- **S10（N65）**：两种实现的 NF 都差 0.4–1.0 dB（要求 ≤ 3.5 dB）。
- **v2 在 S5 上不如 v1**：v2 + Codex 在宽带输入匹配上细化不足；加倍预算也没有改善（docs/133 §7）。
- **"LLM 是关键"**：在 N65 上 v1 规则同样能做 S9，LLM 的优势只体现在 Spectre 用量和代理后端的 S9s/S10s 上。

## 6. 边界

1. 两种 PDK 结果都是原理图级、理想无源、无版图寄生；时间是等效 EDA 时间，只能做相对比较。
2. LLM 用订阅额度（Codex 为主，Claude 只有补充数据）；论文的多个 API 主干与成本表无法对照。
3. 资源护栏（每设计 Spectre 上限、总账本）不是论文设置；碰到护栏的运行已在 docs/133 中单独标注。
4. 单个 seed 的波动很大，结论都以 5 seed 为准，仍属于小样本。
