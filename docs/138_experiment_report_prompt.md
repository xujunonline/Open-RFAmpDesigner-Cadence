# 138 提示词：生成提交导师的《v2 阶段实验报告》

> 用途：在本仓库根目录打开 Claude Code，把下方"提示词正文"整段粘贴给它。
> 它会阅读任务说明、实验记录与原始结果，重算关键数字，写出 `docs/139_experiment_report.md`。
> 报告对应 `docs/130_v2_kickoff.md` 规定的任务（A 线 v2 智能体、B 线 TSMC N65 工艺），覆盖到 `v2.0` 封版及之后的补充实验。
> 读者、报告要素、证据规则、统计要求和自检清单都已写在提示词里，可按需删改。

---

## 提示词正文

````text
你是一名射频集成电路与 EDA 方向的研究助理，负责把本仓库 v2 阶段的工作整理成一份提交给导师的正式实验报告。
报告要让导师在不看代码的情况下判断以下几点：
(1) 做了哪些实验，为什么这样设计；
(2) 每个实验是怎样执行的，中途出了什么问题、如何处理；
(3) 结果是什么，可信到什么程度；
(4) 与原论文相比，哪些复现了，哪些没有，原因是什么；
(5) 下一步值得做什么。

# 读者
- 导师：射频集成电路或 EDA 方向的教师，熟悉 LNA 设计、Spectre 仿真和 PDK，不一定熟悉 LLM 智能体。
- 导师最关心：方法是否正确、实验是否严谨、数字是否可追溯、结论是否过度、与论文的差距是否说清。
- 因此：先给结论，再给证据；每个数字都能追溯到原始文件；不夸大，不回避失败。

# 任务范围
- 主体：docs/130_v2_kickoff.md 规定的 v2 阶段任务，包括：
  - 阶段 0；
  - A 线：A1、A2、A3；
  - B 线：N0–N3；
  - 后续追加的 B/C/D/E 实验、Fig. 9/11-like、实验 a（v2 自进化）、实验 b（Spectre 锚点）；
  - v2.0 封版。
- 背景：v1 阶段（docs/115–129）只作为基线和背景，用一节简述，不展开。

# 必读材料（按优先级）
1. 任务与规则：docs/130_v2_kickoff.md、CLAUDE.md、docs/00_index.md
2. 实验记录（主要依据）：
   - docs/131_agent_v2_design.md
   - docs/132_n65_bringup.md
   - docs/133_agent_v2_results.md
   - docs/134_macbook_handoff.md
   - docs/135_v2_reproduction_report.md
3. v1 背景：docs/115、docs/125、docs/127（只取基线数字与结论）
4. 原始结果：
   - results/repro/n65/（n2、n3 与 spectre_ledger.csv）
   - results/repro/v2_a3/ 下各子目录（smoke、s9s10s、s9s10s_r2、n65、n65_s9s10、n65_b_s5_2h、n65_c_rev2、n65_d3_spiral、fig10_v2、n65_b2_anchors、n65_b2_anchors_v2、figures）
   - results/repro/2026-10-03/（v1 代理基线）
5. 版本记录：git log、git tag（v1-decision-points、v1.1-clean、v2-agentic-alpha、v2.0）、各 PR 的标题
6. 论文：references/paper/RFAmpDesigner_中文翻译.md（只用于对照结论和设置，不大段摘抄）
7. 原理背景（需要时）：docs/137_student_guide.md

# 硬性规则
1. 不编造。报告中的每个数字都必须来自原始结果文件或上面列出的文档，并注明出处路径（必要时加节号）。
   关键数字必须从原始 JSON/CSV 重新计算：
   - 写一个脚本 scripts/report/make_report_tables.py，输出到 results/report/（CSV 表与统计结果）；
   - 重算范围包括：各实验的通过数、Spectre 用量（按阶段对账本求和）、等效时间、LLM 调用与 token、主要指标。
   重算值与文档不一致时，以原始文件为准，并在附录"差异记录"中列出两者和原因。
2. 证据分级，每个结果旁都要标注：
   - 代理（surrogate，趋势级）；
   - PDK 原理图级（TSMC 65 nm 或 40 nm 晶体管、理想无源、无版图寄生，Stage 4 由 Spectre 判定）；
   - 论文原文数据。
   不得把任何结果写成硅结果或后仿结果，不得填入论文表格的"实测"位置。
3. 保密，以下内容不得写进报告：
   - PDK 模型文件路径、器件子电路名、工艺角段名、器件参数和器件表数值；
   - config/*.local.yaml 的内容；
   - 虚拟机 IP 地址、主机名、用户名、密钥路径、任何账号或凭据。
   工艺只写到"TSMC 65 nm LP RF（CRN65LP v1.7）"这一层级。
4. 只读，不做新实验：
   - 不执行任何远程或 Cadence 操作（ssh、bench pdk-*、--backend pdk|cadence）；
   - 不运行花费 LLM 额度的命令；
   - 只运行本地离线脚本（重算表格、画图、统计检验）。
5. 统计要求：pass@1 一律写成"通过数/总数"，并附 95 % Wilson 置信区间。以下关键比较给出 Fisher 精确检验的双侧 p 值，并明确说明样本量小：
   - N65 S1–S8：v1 24/40 对 v2 21/40；
   - S9s/S10s：v2 6/10 对 v1 0/10；
   - N65 S5：v1 4/5 对 v2 1/5。
   p 值不显著时，不得写"显著优于"。
6. 运行间波动：v2（LLM 驱动）同一 seed 的不同运行可能结果不同（见 docs/133 §12b），讨论 v1/v2 差异时必须提到这一点。
7. 资源护栏：每设计 Spectre 上限、总账本、LLM 调用上限都不是论文设置。碰到护栏的运行要单独标注，并说明它对结论的影响。
8. 论文内容只做概括和对照，单次引用原文不超过一两句。
9. AI 工具使用如实说明：
   - 本阶段的代码编写、实验执行与文档整理，由用户指挥 Claude Code 完成；
   - 实验中的 LLM 主干是 Codex（ChatGPT 订阅）和 Claude（订阅）。
   在报告末尾写"AI 工具使用说明"一节，措辞留给用户确认。
10. 全文用中文学术写作风格。图表编号连续（图 1、表 1……），每个图表都有标题、数据来源路径和证据等级。
    单位用 SI，公式用 LaTeX，参考文献用 GB/T 7714 格式。

# 报告结构（按此组织）
封面信息：题目、姓名、学号、导师、课程或项目名称（以"【待填】"占位）、日期、仓库与版本（私有仓库名、标签 v2.0 及其提交号、报告依据的 main 提交号）。

摘要（300–500 字）与关键词（4–6 个）；另附英文摘要（可选）。
要写清：目标、方法、主要结果（带数字与证据等级）、主要结论与局限。

第 1 章 引言
  1.1 研究背景：RF LNA 自动化设计的难点；LLM 智能体方法
  1.2 原论文概述：RFAmpDesigner 的方法要点与主要结论（Table IV/V、Fig. 5/9/10/11）
  1.3 前期工作（v1）简述：代理复现、crn40lp PDK pass@1 29/40（原记 34/40 为加法错误）、Table V 未复现（引用 docs/125、127）
  1.4 本阶段目标：docs/130 的 A 线、B 线目标及验收标准；为什么要在 N65 上先跑 v1 基线
  1.5 报告结构

第 2 章 实验对象与方法
  2.1 设计对象：三级宽带 LNA 拓扑、设计变量、规格 S1–S10（含 S9s/S10s 的定义与理由）
  2.2 设计流程：四个工具与多保真分工、等效 EDA 时间记账
  2.3 智能体实现：v1（规则加两个 LLM 决策点）与 v2（三个 LLM ReAct 智能体）的对比表
  2.4 仿真后端：代理引擎；PDK 表征加 Spectre 判定（混合后端）；锚点选项
  2.5 评价指标与判定：六项违规量、pass@1、等效时间、Spectre 次数、LLM 调用与 token
  2.6 与论文设置的差异表：工艺版本、无源器件、版图寄生、预算口径、硬件、LLM 主干、护栏等。每一行说明对结论可能的影响方向

第 3 章 实验环境
  3.1 硬件：本机（macOS Intel）与 Cadence 虚拟机（核数、IC 版本）。只写文档中已有的信息
  3.2 软件：Python 与依赖版本、Spectre/IC 版本、codex CLI 与 claude CLI 版本（取自 docs/134 等记录）
  3.3 工艺：TSMC 65 nm LP RF（CRN65LP v1.7），原理图级；旧工艺 crn40lp 仅用于 v1
  3.4 版本管理与可复现性：分支、标签、PR、账本；离线复现命令

第 4 章 实验设计
  4.1 实验总表：每行一个实验。列为：编号、目的、自变量、对照组、规格与 seed、预算、护栏、Spectre 用量、LLM 调用、原始档路径、对应文档节。
      至少覆盖：阶段 0、A1、A2、A3 冒烟、A3 S9s/S10s、A3 N65 S1–S8、N0、N1、N2、N3、B、C、D、E（S9/S10 及 S10 加跑）、Fig. 9/11-like、a、b（v1）、b（v2 及重跑）
  4.2 对照设计的逻辑：
      - 同工艺比较 v1 与 v2，分离智能体与工艺的影响；
      - 同一 seed 比较锚点是否用 Spectre；
      - 代理与 PDK 互为补充
  4.3 资源预算：Spectre 上限的历次调整及理由（1500 → 2000 → 2400 → 3000 → 3300，日期与用途取自 docs/130）；LLM 调用上限

第 5 章 实验过程记录（重点章节）
  5.1 时间线：日期、阶段、事件。日期取自 git log、账本时间戳和文档，不确定的标"约"
  5.2 逐个实验记录：每个实验按"目的 → 配置与命令 → 执行过程 → 资源消耗 → 原始档 → 小结"写。
      命令给完整的 bench 子命令或队列文件名，不写主机信息
  5.3 异常与处理汇总表：每行写现象、原因、处理、对结果的影响、是否作废。至少包括：
      - codex alpha 版间歇路由错误（改用正式版并加重试）；
      - 虚拟机 DHCP 地址变化导致 v2 S10 seed 2 中断后重跑；
      - ssh 连接失败只在"未连上"时重试；
      - 队列输出目录重名；
      - 误操作重复运行（184 次 Spectre，不用于结果）；
      - 中止的三端口表征（12 次，不用于结果）；
      - 护栏触发的运行；
      - v2 增益要求为 null 时崩溃、pdk3 cs2 模式错误等代码缺陷修复。
      依据 docs/132–134 与 docs/135 §5
  5.4 资源消耗汇总：Spectre 按阶段求和（与账本 CSV 一致，总计 3144/3300）；LLM 调用与 token（按实验汇总，取自结果 JSON 的 llm_usage）

第 6 章 实验结果
  每节先给表或图，再写两三句读法。至少包括下列内容。
  6.1 N65 PDK：v1 基线 S1–S8，5 seed，逐规格表，与 crn40lp、论文对照
  6.2 N65 PDK：v2 + Codex S1–S8，与 v1 逐规格对照（含 Wilson 区间、Fisher 检验）
  6.3 代理：S9s/S10s v2 + Codex 对 v1（含统计检验）；修订 2 提示词（实验 C）
  6.4 N65 PDK：原始 S9/S10（v1 与 v2，含 S10 加跑），Spectre 用量对比
  6.5 实验 B（S5 预算加倍）与实验 D（PDK 螺旋电感）
  6.6 Fig. 9-like、Fig. 11-like：使用已有图 results/repro/v2_a3/figures/fig9_like.png 和 fig11_like.png
  6.7 实验 a：v2 自进化（Fig. 10 流程）；图用 results/repro/v2_a3/figures/fig10_v2_like.png
  6.8 实验 b：Spectre 锚点（v1 三个设计，v2 两个设计及重跑），逐指标对照表
  6.9 引擎与 Spectre 一致性（docs/132 §4 的 pdk-check 对比）
  需要新图时，只能由脚本从原始文件生成，保存到 results/report/figures/，并在图注中写明生成脚本

第 7 章 分析与讨论
  7.1 与论文逐条对照：复现、部分复现、未复现、无法对照四类，每条附证据
  7.2 v1 与 v2：通过率、Spectre 用量、LLM 成本、运行间波动；"LLM 是否关键"的判断及其证据边界
  7.3 工艺影响：crn40lp 29/40 对 N65 24/40，差距全部来自 S3；器件 fT 与 NFmin 的诊断
  7.4 未复现规格的原因分析（S3/S6/S7/S10），以及 v2 在 S5 上偏弱的原因
  7.5 多保真分工的检验：实验 b 说明了什么，没说明什么
  7.6 效率与成本：等效时间、Spectre 次数与论文口径的差异（docs/135 §5.1）

第 8 章 有效性威胁与局限
  分四类，每条说明可能使结论偏向哪个方向：
  - 内部效度：代理模型、等效时间模型、护栏、LLM 波动、实现缺陷与修复；
  - 外部效度：原理图级、理想无源、无寄生、单一工艺角；
  - 构造效度：S11 ≤ −10 dB 的项目约定、FoM 公式由用户选定；
  - 统计结论效度：样本量。

第 9 章 结论与后续工作
  9.1 结论：分条，每条带证据等级
  9.2 后续工作建议：按"预期收益、所需资源（Spectre 次数、LLM 额度、时间）、风险"列表，
      例如带版图寄生的验证、更多 seed、S5 匹配策略、更高 Q 无源等。只写"建议"，不承诺结果

参考文献（GB/T 7714）：原论文、Hillbrand–Russer、ReAct、PSO 等方法文献，以及报告中引用的教材

附录
  A 命令与队列清单（scripts/jobs/ 下与本阶段有关的队列文件及用途）
  B Spectre 账本汇总：按阶段求和；与 CSV 合计的对账
  C 版本记录：标签、PR 编号与标题、关键提交
  D 原始档目录清单与说明
  E 差异记录：重算值与文档值的不一致
  F 术语表
  G AI 工具使用说明（草稿，标"请用户确认"）
  H 报告自检记录（见下）

# 写作要求
- 每章开头一两句说明本章内容，结尾三至五条小结。
- 结论句都要能在正文或附录中找到对应的表、图或原始文件。
- 失败结果与成功结果同等详细。
- 用"本实验""本阶段"作主语，不用夸张措辞。

   - [ ] 每个结果都标注了证据等级
````

## 使用说明

- 如果导师只要短版，可以在提示词末尾加一句"正文控制在 8000 字以内，第 5 章只保留时间线和异常汇总表"。
- 如果报告还要覆盖 v1 阶段的完整工作，把"任务范围"中"v1 只作为背景"一条改为"v1 与 v2 并列"，并在必读材料中加入 docs/115–129 的全部文档。
- 统计检验需要 scipy，仓库依赖中已有。
- 需要 Word 版时，生成 Markdown 后再让 Claude Code 转换。本机没有 pandoc，可以用 docx 技能。
