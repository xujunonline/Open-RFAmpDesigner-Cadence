# 125 RFAmpDesigner 复现总报告（截至 2026-10-02，含 docs/126–127）

> **2026-10-09 更新**：加入 v2 智能体与 N65 结果的总报告见 [docs/135](135_v2_reproduction_report.md)；本文保留 v1 的结论不变。

论文：*RFAmpDesigner: A Self-Evolving Multi-Agent LLM Framework for Automated RF Amplifier Design*（arXiv:2605.10093）。
本报告汇总 docs/115–127 的结论。表格与数字均来自 `results/` 下的原始档。

**证据分三级：**
- **代理**（开放 EKV 类器件 + 理想无源，趋势级）。
- **Spectre 宏模型**（v1，用来验证引擎）。
- **示意 PDK 级**（TSMC 40LP RF 器件 + 理想无源 + HB，无版图寄生）。

三者都**不是**论文的 N65 后仿或硅结果，因此不填论文 Table IV/V/VI 的"实测"位置。

## 1. 一句话结论

论文的**方法**已经在本仓库端到端可运行：资源分配式多保真工具中间件、Manager/Searcher/Refiner、KB/EB 自进化，并能接入真实 Spectre。

**复现了的趋势：**
- 工具中间件 + 多智能体明显优于 GA/BO 基线（Table IV 趋势）。
- 多保真频带规划大幅节省仿真（Fig. 5）。
- 记忆复用带来自进化加速（Fig. 10）。

**没有复现的结论：**
- 最难的规格：S6、S7（示意 PDK 上 0/5，论文 2/5、3/5），以及 S9/S10。S3 在代理器件上 0/5，但在示意 PDK 上 5/5。
- "LLM 主干显著优于基线"（Table V）：无论 40 次封顶还是不封顶（论文口径），在订阅额度下都没有得到。

## 3. 未通过任务的原因

**S9/S10（代理）：** 在 30 mA、25 dB 增益下，代理器件的 IP1dB 前沿约 −19.7 dBm，规格是 −15 dBm。这是器件模型上限，与搜索方法无关。

**S7（NF ≤ 2.5 dB）：**
- 示意 PDK 上 4 次 Spectre 运行，最佳 NF 为 2.69–2.80 dB，其余指标都满足。
- 离线分析：器件在 30 GHz 的 NFmin 约 1.0 dB，单元模型与 Spectre 一致（docs/124 §2）。
- 匹配电感 Q = 25 的损耗约占 0.3 dB；这个拓扑的 NF 下限约 2.6–2.7 dB（docs/123 §10）。
- 判断：在理想无源、Q = 25 的条件下不可达。
- 验证（docs/126）：把匹配电感 Q 设为 100，Spectre 3/3 seed 通过（NF 2.39–2.49 dB）；匹配电感理想时 NF 2.29 dB。瓶颈确认是输入匹配损耗。

**S6（±40 % 带宽）：** 宽带下 S11 ≤ −10 dB、增益 20 dB、纹波 ≤ 3 dB 三者冲突，而且 NF 约 5.5 dB，超过 5 dB 的规格。PDK 与代理上都未通过。
- 验证（docs/126 §5）：3× 预算、每设计 40 次 Spectre，seed 0/1 仍未通过（归一化违规 1.05 / 0.72）。NF 与宽带 S11 直接冲突，需要改拓扑，超出论文图 3 的电路。

**S3（50 GHz，代理）：**
- NF 与 IP1dB 对关键级增益的要求方向相反，窗口很窄。
- 论文"Stage 2 不可行即提前终止"会让多数 refine 循环在一步内结束。
- 尝试过的回退策略（B21）反而更差，已放弃（docs/124 §1.3）。

**报告逻辑（B20）：**
- 旧逻辑让失败运行报告最后一次评估，夸大了 Ours 的残余违规。
- 修正后，Ours 在 S3/S6/S9s 上的残余违规小于两种 subtool 基线（docs/124 §1.2）。

## 4. 论文勘误与实现缺陷（详见 docs/116）

- **Eq.(3)**：
  - Y11 分母末项量纲错误，应为 `R_S ω0³ Q s`，已用节点分析测试验证。
  - "/2" 在单端等效下造成约 −6 dB 的系统偏差。
  - 修正式相对 HF 仿真为 −1.2 ± 2.2 dB；印刷式为 −2.4 ± 9.8 dB。
- **Table III**：IP1dB −15 dBm 与正文 OP1dB 9 dBm 在约 24 dB 增益下自洽，不是矛盾。
- **Stage 2 代价函数**：只有 Eq.(1) 时 NF 余量为零（B05）。
- **Refiner**：关键级增益与"到第二级栅极的增益"被混用（B06）。
- **工程问题**：
  - 第一级 Cdb 的物理位置（B11）。
  - Spectre 频点去重（B12）。
  - mcp 2.x 不兼容（B13）。
  - LLM 回退计数口径（B14）。
- **PDK 链路**：
  - 偏置不足与 CG 宽度比（B15）。
  - 噪声与压缩模型偏差（B16）。
  - 中和电容负载漏算（B17）。
  - 第一级必须用三端口 Y（B18）。
  - 器件表选择错误（B19）。

## 5. 引擎与 Spectre 的一致性（示意 PDK）

| 指标 | 初版（docs/121） | 最终（docs/123） |
|---|---|---|
| 中心增益 | 偏差可达 13 dB（欠偏置） | 约 +0.8 dB |
| 带内最差 S11 | 宽带约 1–2 dB 乐观 | 约 0.1 dB |
| NF@fc | 约 1.7 dB 悲观 | 约 ±0.1 dB（k = 1.2 校准） |
| IP1dB | 悲观 8–17 dB | 0 … −4 dB |

关键做法：
- 第一级用在路三端口实测 Y，差分级用实测二端口 Y 加中和电容。
- 拟合噪声模型，并做一次经验噪声校准。
- 用直流转移曲线求大信号 1 dB 点。

用量：Spectre 累计约 697 次（用户已把上限提高到约 1000；P1 用 214 次，docs/127）。

## 6. 复现边界

1. 代理器件与示意 PDK 都不是论文的 N65 工艺。无源器件理想化（Q 恒定），没有版图寄生和 EM 模型。
2. PDK pass@1 已按 5 seed 统计（docs/127 §5），但 seed 0 中 S2/S3/S5/S8 来自更早的模型版本；时间为等效 EDA 时间，不是墙钟。
3. LLM 主干用订阅额度：Claude Pro（seed 0）和 ChatGPT/Codex（5 seed，封顶与不封顶各一组）。时延与论文的 API 设置不同。智能体实现为 v1：Searcher 为程序，LLM 只在 Manager 与 Refiner 两个决策点做选择（论文三个智能体都是 LLM ReAct 循环）。
4. 本仓库的 Spectre 总量上限（400→550→1000）与 40 次 LLM 封顶都是资源保护，不属于论文设置（docs/127）。
5. 等效 EDA 时间是成本模型，按论文"顺序执行"记账，绝对值只能做相对比较。
6. 以下两项是经验校准，物理根因未单独表征：
   - 第一级噪声系数 k = 1.2。
   - IP1dB 偏置。
