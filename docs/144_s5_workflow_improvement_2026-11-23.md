# S5 工作流改进与学习日志（2026-11-23）

## 目标与边界

按用户要求控制用时，允许留下未通过的指标。本次改进 v2 的 S5 决策反馈、预算退出、最佳方案保留与日志；不改 `tools.spec_check`，不降低通过门槛。真实 N65 数据仅回放已有结果，本轮新增真实 LLM = 0、Spectre = 0；没有扩展到多 seed 或器件表征。

S5 是一个规格案例（21–39 GHz），不是单独常驻的 AI。主流程仍由 Manager 调度 Searcher 和 Refiner；新增提示与数据反馈使这些角色能更准确地处理 S5。真实运行中角色通过 LLM 调用选择工具；离线 `scripted` 只验证流程，不检验 LLM 是否理解提示。

## 改动

1. 新增 `src/orfadc/repro/s5_workflow.py`：只分析带内频点，输出增益谷底、增益峰值、最差 S11、最大 NF 的频率与数值。诊断是测量摘要，不把相关性当物理原因。
2. 为 S5 注入明确判据：最低增益 22–28 dB，纹波 ≤3 dB，中心 NF ≤5 dB，IP1dB ≥−25 dBm，全带 S11 ≤−10 dB，电流 ≤30.03 mA（原判据含 0.1% 容差）。全带 NF 最大值仅作诊断，不能误当本项目的通过门槛。
3. 新提示覆盖“仅增益略低”“纹波偏大”“反复 Stage 3 后仍 S11 不通过”。强调小幅尝试后重测全部指标，不能把目标增益变化等同于实际增益变化。
4. S5 Refiner 报告保留其已评估设计中按既有归一化违规评分最好的一个，修正对应候选 ID；评分最小不等于通过，也不保证每个指标都优于其他设计。
5. 同一 Refiner 内重复评估完全相同的设计 ID 时复用结果，避免再次仿真；不跨运行复用、不把不同设计当成同一设计。
6. 新增 `ORFADC_V2_WALL_SECONDS`：按真实墙钟、在动作边界停止派发；嵌套角色共享预算。正在执行的调用允许返回，可能超过设定秒数；不强杀状态不明的远程任务。现有 LLM/EDA/Spectre 限额仍保留。
7. 修复嵌套调用的日志归属：Manager 返回时更新自己的请求记录，避免覆盖子角色最后一条记录。此修复作用于 v2；S5 专项行为须显式开启。
8. 结果文件标记 `_s5wf1`，JSON 记录新工作流和限时设置；诊断放在观测前部，避免被长结果截断。

开关：`ORFADC_V2_S5_WORKFLOW=1`；兼容原有 `ORFADC_V2_S11_BACKTRACK=1`。关闭 S5 开关恢复原有专项行为。没有重写器件物理模型或匹配优化器，也没有声称提高真实 PDK 成功率。

## 工作日志：给初学者看的版本

| 步骤 | 做了什么 | 为什么这样做 |
|---|---|---|
| 1 | 对照真实结果和 `spec_check` 核对门槛 | 先确认“考什么”，避免用错另一规格的 IP1dB 或 NF 条件 |
| 2 | 从整条曲线找峰、谷和最差匹配频率 | 一个中心增益数字不能说明全带是否满足要求 |
| 3 | 把诊断送给 Refiner，并保留 Manager/Searcher 职责 | Refiner 负责局部修改；Manager 决定换候选，Searcher 生成方案 |
| 4 | 区分抬高增益与减小纹波 | 整体抬高会同时抬高峰和谷，峰谷差不会因此减小 |
| 5 | 每次修改后仍做全指标评估 | 提高增益可能损害噪声、匹配或线性，不能只看一个指标 |
| 6 | 保留最好结果、重复设计不重算、到预算退出 | 允许试错，但不丢失已取得的进展、不无限消耗仿真 |
| 7 | 运行离线流程与回归测试 | 先确认程序和记账正确，再投入昂贵真实验证 |

调试中发现日志断言直接比较完整浮点值与日志四位小数导致一次测试失败；按既有日志格式统一精度后修正。首次队列命令多写了 `scripts/` 前缀，未找到队列、未执行设计；修正后执行一次完整队列。这两项都没有真实调用消耗。
